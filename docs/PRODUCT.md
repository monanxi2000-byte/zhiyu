# 知遇 ZhiYu · 产品说明 / 计划书

> 知乎黑客松 2026 · 校园新锐季 · 队伍「邂逅」 · 赛道：学习工具与知识生产
>
> 作品方向：**多 Agent 协作完成资料整理、观点对照与知识梳理**（面向刚进入各领域的新人：学生、职场新人）

---

## 一、一句话介绍

**知遇** 是一个基于知乎知识生态的「AI 新人引路助手」：用户输入一个想进入的领域（如"数据分析入门""考研数学""转行程序员"），五个 AI Agent 协作把知乎上散落的优质经验，整理成 **可执行的学习路径、可对照的观点地图、可复习的知识卡片、可实践的项目任务、可分享的共创内容**。

## 二、核心创作思路

### 1. 问题：新人入行的真实困境

当我们第一次想进入一个新领域时，普遍遇到四个问题：

| 困境 | 表现 | 根因 |
|---|---|---|
| **信息过载** | 搜出几百条回答，不知道先看哪条 | 知乎有海量优质内容，但没有"为你整理好"的入口 |
| **观点冲突** | "先学 A"和"先学 B"都有高赞，听谁的？ | 经验型社区天然存在分歧，新人缺乏对照与判断框架 |
| **看了就忘** | 收藏夹吃灰，学完没有产出 | 知识只被"看见"，没有被组织成可吸收、可复习的结构 |
| **学用脱节** | 学了理论但不会实践，缺乏项目经验 | 学习路径停留在"看"的层面，没有"做"的引导 |

### 2. 解法：用多 Agent 协作解决"整理、对照、梳理、实践、共创"

本项目不做一个"搜一下给你十条链接"的工具，而是把知乎的内容生产链路再加工一层：

```
用户输入领域
    │
    ▼
┌─────────────────────────────────────────────────┐
│  Agent 1 · 资料收集官                             │
│  知乎搜索 + 全网搜索 + 知乎知识内容 + 热榜         │
│  → 8维度多关键词并行搜索、去重、筛选、排序         │
│  → 产出30条知乎优质资料 + 20条全网资料            │
├─────────────────────────────────────────────────┤
│  Agent 2 · 观点对照官                             │
│  识别核心讨论 → 提炼分歧与共识                     │
│  → 产出观点对照表（每条观点标注来源和立场）         │
│  （实时模式叠加知乎直答生成观点综述）              │
├─────────────────────────────────────────────────┤
│  Agent 3 · 知识梳理官                             │
│  资料 → 分阶段学习路径 + 核心概念 + 复习卡片       │
│  → 每个阶段/概念附带知乎推荐资源和案例卡           │
│  → 产出可执行、可复习的结构化知识                 │
├─────────────────────────────────────────────────┤
│  Agent 4 · 实践官                                 │
│  基于学习路径生成可执行的小项目任务                 │
│  → 目标/步骤/资源/验收标准/预计时间                │
│  → 让用户从"看懂"到"做到"                        │
├─────────────────────────────────────────────────┤
│  Agent 5 · 答疑官                                 │
│  基于个人知识库的 RAG 问答                         │
│  → 关键词提取 + 相关度计算 + 知乎搜索补充          │
│  → 随时解答学习过程中的疑问                       │
└─────────────────────────────────────────────────┘
    │
    ▼
输出：学习路径 / 观点对照 / 概念卡 / 复习卡片 / 精选资料 / 相关热点 / 实践任务 / 答疑
    │
    ▼
内容共创：一键生成知乎文章（入门指南/经验分享/观点整理/复习卡片合集），发布回知乎
```

五个 Agent 各司其职、顺序协作，通过"任务书"（中间产物对象）传递信息，全程以 SSE 向前端推送实时进度，让用户直观看到"资料正在被整理、观点正在被对照、知识正在被梳理、任务正在被生成"的过程。

### 3. 为什么"多 Agent"而不是一个全能问答

- **可解释**：每个 Agent 的产出边界清晰，观点对照必须标注来源，避免"黑盒回答"
- **可验证**：资料、观点、路径、任务四份产出彼此独立又互相支撑，评委可以逐项核查
- **可演进**：Agent 之间是模块化流水线，未来可替换或新增 Agent（如"错题官""复盘官"）
- **可实践**：不仅告诉你"学什么"，还告诉你"怎么做"，从理论到实践闭环

## 三、目标用户与场景价值

### 目标用户
1. **学生**：考研数学、高考志愿、大学选专业、学习方法与专注力
2. **职场新人**：转行编程、数据分析入门、产品经理入门、自媒体起步、职场沟通

### 典型使用场景
- 一个想转行数据分析的人，3 分钟拿到"工具三件套 → 方法论 → 作品集"的完整路线，看到"先学 SQL 还是先学 Python"的正反观点与共识，还能获得一个可执行的小项目任务
- 一个考研学生，输入"考研数学"即获得分阶段规划、核心概念卡、复习卡片，还能设置复习提醒，用间隔重复法巩固记忆
- 一个完全自定义的领域（如"考古学"），走通用框架自动生成入门路径、实践任务和答疑服务
- 一个学完想分享的用户，一键把学习成果生成知乎文章，发布回社区，形成"输入→整理→实践→输出"的完整闭环

## 四、整体技术方案

### 架构
```
浏览器（原生 HTML/CSS/JS 单页，无构建依赖，3D 沉浸式视觉）
    │  SSE 进度流 + REST API
    ▼
Node.js + Express 后端
    ├── 多 Agent 编排器（orchestrator）
    │     ├── Agent 1 资料收集官（collector）
    │     ├── Agent 2 观点对照官（comparator）
    │     ├── Agent 3 知识梳理官（curator）
    │     ├── Agent 4 实践官（practitioner）
    │     └── Agent 5 答疑官（qaOfficer）
    ├── 知乎 CLI 封装（zhihuClient，带 TTL 缓存）
    ├── 黑客松内容接口封装（knowledgeApi）
    ├── 知乎 OAuth 模块（zhihuOAuth）
    ├── 用户数据存储（userStore，文件系统持久化）
    └── 内容共创模块（contentShare，4种知乎文章格式）
```

### 技术要点
- **凭证安全**：Access Secret 只存在于后端环境变量（`ZHIHU_ACCESS_SECRET`），经官方 CLI 调用，绝不进入前端、URL 或日志
- **缓存与配额**：所有开放能力调用均带应用层 TTL 缓存（搜索 1h、热榜 15min、直答 6h），遵守官方"应用层缓存、请求去重"要求
- **双模式设计**：未配置凭证时以"演示模式"运行（真实知识内容接口 + 内置素材，逐条标注）；配置凭证后自动切换"实时模式"（真实搜索/热榜/直答）
- **优雅降级**：任一接口失败均有真实错误提示与降级路径，不假装成功
- **用户系统**：知乎 OAuth 授权码模式登录，含 state 防 CSRF，用户数据（学习路径/复习卡片/收藏）文件系统持久化
- **间隔重复**：基于 SM-2 算法的复习提醒系统，浏览器通知，定时检查，复习统计
- **RAG 问答**：答疑官基于个人知识库的检索增强生成，关键词提取 + 相关度计算 + 知乎搜索补充
- **内容共创**：4 种知乎文章格式一键生成（入门指南/经验分享/观点整理/复习卡片合集），每个内容条目带分割线和来源标注

### 视觉与交互创新
- **沉浸式 3D 宇宙背景**：5000+ 星星、4 个星云、银河带、流星、行星，滚动穿梭效果，鼠标视差
- **知识星球系统**：中央知识核心 + 轨道行星（学习阶段），悬停放大、点击聚焦、进度发光
- **玻璃拟态 UI**：毛玻璃效果卡片，半透明叠加，与宇宙背景融合
- **深色/浅色双主题**：全局文字阴影，确保所有文字清晰可读
- **流星交互效果**：观点对照出现时触发流星数据流视觉反馈
- **主题同步**：切换主题时 3D 场景背景色同步变化

## 五、使用的知乎开放能力

| 能力 | 用途 | 调用方式 |
|---|---|---|
| **知乎搜索** | Agent 1 搜集领域优质问答（8维度多关键词并行，标题/摘要/作者/链接/权威度） | 官方 CLI `search zhihu` |
| **全网搜索** | Agent 1 补充知乎之外的权威来源 | 官方 CLI `search global` |
| **知乎热榜** | 结果页"相关热点"板块，保持话题时效性 | 官方 CLI `hot` |
| **知乎直答** | 实时模式下 Agent 2 生成观点综述 | 官方 CLI `answer`（zhida-fast） |
| **黑客松知识内容接口** | Agent 1 匹配领域知识文章，精选资料卡片与阅读弹窗 | HTTP `hackathon/v2/knowledge/*`（无鉴权） |
| **黑客松故事接口** | 预留能力（互动叙事方向扩展） | HTTP `hackathon/v2/story/*`（无鉴权） |
| **知乎 OAuth 2.0** | 用户登录，保存学习路径，同步收藏夹，生成个人知识库 | 授权码模式（含 state 防 CSRF） |

> 能力边界：单用户热榜 100 次/天、直答 100 次/天、搜索 5000 次/天。全部调用带缓存与限流，热榜 15 分钟刷新一次，不高频轮询。

## 六、与知乎社区生态的契合点

1. **内容即产品**：产品的"原材料"就是知乎社区的优质回答与知识内容，知乎越繁荣，知遇的引路质量越高
2. **回流价值**：每份学习路径都链回知乎原文、标注原作者；用户在"精选资料"里点击即可回到知乎阅读，把流量还给社区
3. **延长内容生命周期**：知乎回答天然是"问答形态"，知遇把它再加工为"路径/卡片/对照表/任务"形态，让老内容在新场景（学习、复习、实践）中被反复使用
4. **内容归属透明**：观点对照逐条标注来源，知识文章展示原作者与版权说明，不将原文改写成应用创作
5. **共创闭环**：用户学完后可一键生成知乎文章发布回社区，形成"知乎内容→AI整理→用户学习→用户创作→知乎内容"的完整生态闭环
6. **用户沉淀**：通过知乎 OAuth 登录，用户的学习数据、收藏、复习计划都与知乎账号绑定，增强用户粘性

## 七、对社区用户的实际价值

- **节省决策时间**：把"看 100 条回答"压缩成"看 1 份对照表 + 1 条路径 + 1 个任务"
- **降低入门门槛**：为"知道知乎好却不知道从哪看起"的新人提供结构化入口
- **促进知识吸收**：复习卡片与间隔重复算法让用户"记住"知识，而不是"看过"
- ** bridging 学用鸿沟**：实践官生成可执行的小项目任务，让用户从"看懂"到"做到"
- **随时答疑解惑**：答疑官基于个人知识库 RAG 问答，学习过程中有问题随时问
- **促进知识生产**：内容共创让用户"吸收→整理→输出"，鼓励用户带着理解回到知乎参与讨论、输出内容
- **覆盖真实人群**：考研、转行、自媒体、高考志愿……都是知乎上真实存在且需求旺盛的场景
